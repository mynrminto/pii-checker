個人情報チェッカー

クラウドAI・SNS・公開ページ等に貼る前に、個人を特定しうる情報や要配慮個人情報が含まれていないかを判定します。
判定はすべてこのブラウザの中で行われ、入力したテキストはどこにも送信・保存されません（サーバーが存在しません）。

これはスクリーニングであり、安全を保証するものではありません。
小型のAIモデルと機械的なパターン検出による一次チェックです。見落とし・誤検出があり、「問題なし」と出ても個人が特定できる可能性は残ります。 書き換え案を使う場合も、最終的な確認と責任は利用者ご自身にあります。

方針：必要十分な最低限の匿名化。個人を特定できなくするために必要な部分だけを削り、臨床的に意味のある情報（疾患・検査・治療、年代、性別、症状と経過）は最大限残します。

考え方と仕組み

外部AIに貼る前の匿名化

原則は必要十分な最低限の匿名化。個人を特定できなくするために必要な部分だけを削り、臨床的に意味のある情報は最大限残します。

1残す・一般化・削る

残す
臨床的に意味があり、識別子にならない
  • 疾患名・検査・治療・薬剤（稀少疾患も）
  • 年代（学童期、40代）
  • 性別
  • 症状と経過の論理
一般化
情報は残しつつ精度を落とす
  • 5歳 → 幼児期、47歳 → 40代
  • 2024年3月13日 → 基準日＋3日
  • 116歳 → 100歳以上（同意要検討）
  • 国内2例目 → 極めて稀な
削る
識別に直結し、臨床的な意味が薄い
  • 氏名・イニシャル・ID・連絡先
  • 市町村以下の地名、施設名、「当院」
  • 受診日などの暦日、「昨日の当直で」
  • 学校名・職業・家族構成
単独では無害でも、組合せで一人になる

氏名がなくても準識別子が重なると特定されます。稀少疾患や届出・公表される感染症は、公的な発表と照合されやすい「特異な記述」です。

116歳＋屋久島＋ジカ熱＝事実上一人に特定
100歳以上＋（地名削除）＋ジカ熱＝疾患の情報は残る
法律の視点：容易照合性

文章から氏名を消しても、書き手の手元にはカルテがあり照合できるため、法律上は書き手の側からは個人情報のままです。「外部から特定できないか」の前に「患者の記述を外に出す必要があるか」を考えます。

入力先の視点：契約で決まる

個人契約の一般向けAIは入力が保持される規約が多く「第三者提供」に近い扱いです。「保存しない・学習に使わない」を契約で担保した組織契約なら「委託」。可否は院内規程で決まります（医療情報システム安全管理GL 7.0版 Q&A 企画管理編 Q18）。

2ツールの仕組み — すべてブラウザの中で完結

入力
貼り付けたテキスト

症例要約、質問文、発表原稿など。どこにも送信・保存されません。

→
ルール層（即時・決定論的）
検出・書き換え・根拠

正規表現で氏名・連絡先・地名・日付・年齢を検出。指定難病348＋届出感染症のリストで特異な記述を判定。組合せを評価し、書き換え文と変更理由を生成。

→
AI層（WebGPU・任意）
短い判定と希少性推定

小型LLM（1.5〜3B）をブラウザ内で実行。文脈を読んだ所見と、リスト未収載の疾患名の希少性を推定。ルールの「入力不可」は下げません。

→
出力
入力不可注意問題なし

判定＋書き換え案＋変更箇所と理由。コピーしてそのまま使えます。

なぜ「書き換え」はルールに任せるのか

ブラウザで動く小型モデルに文章を書き換えさせると「質問に答える」か「一字も変えない」かになり、稀少疾患名を消してしまうこともありました。確実性と根拠が要る工程は決定論的に、文脈の判断だけをAIに任せています。

送信していないことを自分で確かめられる

静的サイトでサーバーが存在しません。判定中の外部通信件数をページ上部に表示し、Wi-Fiを切っても動作します。広告・アクセス解析なし、ソースコードは公開。
