確かめ方
① 開発者ツール（F12）の Network タブを開いたまま「判定する」を押しても、新しい通信は発生しません（初回のモデル取得を除く）。
② モデル読み込み後に Wi-Fi を切っても判定できます。
③ 静的ファイルだけで構成され、受け取るサーバーが存在しません。ソースコードで確認できます。

外部AIに貼る前に、
誰のことか分からない文章にする。

クラウドAI・SNS・公開ページに出す前のテキストを、ブラウザの中だけで判定します。個人を特定しうる情報を見つけ、必要最小限の書き換え案と、その根拠を示します。

残すのは疾患・検査・治療、年代、性別、経過。削るのは氏名・連絡先・市町村以下の地名・施設名・暦日・職業。知りたい内容が消える書き換えはしません。

これはスクリーニングであり、安全を保証するものではありません。ルールと小型モデルによる一次チェックには見落としも過検出もあります。「問題なし」と出ても最終判断は利用者ご自身と所属施設の規程に従ってください。

考え方と仕組み

原則は「必要十分な最低限の匿名化」。個人を特定できなくするために必要な部分だけを削り、臨床的に意味のある情報は最大限残します。

残す・一般化・削る

残す
臨床的に意味があり、識別子にならない
  • 疾患名・検査・治療・薬剤（稀少疾患も）
  • 年代（学童期、40代）
  • 性別
  • 症状と経過の論理
一般化
情報は残しつつ精度を落とす
  • 5歳 → 幼児期、47歳 → 40代
  • 2024年3月13日 → 基準日＋3日
  • 116歳 → 100歳以上（同意要検討）
  • 国内2例目 → 極めて稀な
削る
識別に直結し、臨床的な意味が薄い（学会指針）
  • 氏名・イニシャル・ID・連絡先
  • 市町村以下の地名、施設名、「当院」
  • 受診日などの暦日、「昨日の当直で」
  • 学校名・職業・家族構成
単独では無害でも、組合せで一人になる

氏名がなくても準識別子が重なると特定されます。稀少疾患や届出・公表される感染症は、公的な発表と照合されやすい「特異な記述」です。

116歳＋屋久島＋ジカ熱＝事実上一人に特定
100歳以上＋（地名削除）＋ジカ熱＝疾患の情報は残る
法律の視点：容易照合性

文章から氏名を消しても、書き手の手元にはカルテがあり照合できるため、法律上は書き手の側からは個人情報のままです。「外部から特定できないか」の前に「患者の記述を外に出す必要があるか」を考えます。

入力先の視点：契約で決まる

個人契約の一般向けAIは入力が保持される規約が多く「第三者提供」に近い扱いです。「保存しない・学習に使わない」を契約で担保した組織契約なら「委託」。可否は院内規程で決まります（医療情報システム安全管理GL 7.0版 Q&A 企画管理編 Q18）。

ツールの仕組み

入力
貼り付けたテキスト

症例要約、質問文、発表原稿など。どこにも送信・保存されません。

→
AI層（WebGPU・任意）
固有名の抽出と希少性推定

小型LLM（1.5B）をブラウザ内で実行。辞書にない氏名、接尾辞のない地名、施設名、職業を本文から抜き出し、本文に実在するか・名前らしい形かを検証。リスト未収載の疾患名の希少性も推定。判定はしません。

→
ルール層（決定論的）
検出・判定・書き換え・根拠

正規表現・姓辞書・疾患リスト（指定難病348＋小児慢性特定疾病＋届出感染症）で検出し、AIが抽出した語も合流。準識別子の組合せを評価して判定を決め、書き換え文と変更理由を生成。AIを使わない場合も、ここだけで即時に動きます。

→
出力
入力不可注意問題なし

判定＋書き換え案＋変更箇所と理由。コピーしてそのまま使えます。

貼り付けた直後にルール層が先に走って暫定結果を表示し、AI抽出が終わると同じルール層で再判定します。ルールが常に最終判定者です。

AIは「抽出器」、ルールが「判定器」

小型モデルは判定や書き換えを任せると誤りが多い一方、「本文中の人名・地名を抜き出す」作業は正確です。そこで AI には抽出だけをさせ、抽出した文字列が本文に実在することを検証してから、ルール層が判定・置換します。

送信していないことを自分で確かめられる

静的サイトでサーバーが存在しません。判定中の外部通信件数を上部に表示し、Wi-Fi を切っても動作します。広告・アクセス解析なし、ソースコードは公開。
